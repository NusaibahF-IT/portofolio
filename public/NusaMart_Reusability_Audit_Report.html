Prompt Library — Tiga Reusable Specs

PL-01 Parameterization Review

INPUT
Reusable pipeline Python, config baseline.json dan july.json. Fokus peserta: Baseline dan July, periksa apakah ada parameter jalur path seuai atau ada yang masih harcode di script pipelinenya.

TASK
Temukan nilai hardcoded, jelaskan risiko, dan nilai apakah satu kode mendukung input periode berbeda.

RULES
Jangan ubah grain (1 order/baris), arti kolom, nilai transaksi, atau nonaktifkan validasi. Bedakan temuan pasti dan dugaan.

EXPECTED OUTPUT
Tabel: komponen | bukti | risiko portability | usulan tindakan minimal.

VERIFICATION
Bandingkan config dan bukti dua run. Baseline dan Juli harus PASS dengan source Python sama tanpa edit.

PL-02 Failure Diagnosis

INPUT
Run report JSON, event log JSONL, dan konfigurasi skenario terkait. Fokus peserta: JSON Error dan Run Report error yang perlu diperhatikan, keduanya atau salah satu error saat skenario missing input dan schema drift.

TASK
Jelaskan penyebab STOP/WARNING, langkah terdampak, jenis error, dan tindakan minimal.

RULES
Jangan menyembunyikan error, memalsukan nilai, menonaktifkan validasi, atau menganggap semua STOP sebagai PASS.

EXPECTED OUTPUT
Tabel: scenario | error/warning evidence | probable cause | safe response | minimal repair.

VERIFICATION
Periksa actual_status, error_type, event log RUN_END, dan apakah CSV final sesuai aturan.

PL-03 Stress-Test Review

INPUT
Matriks lima skenario expected/actual, run reports, dan log terkait. Fokus peserta: Dari kelima skenario, evaluasi kesesuain expected dan actual status, kemudian simpulkan workflow dari lima variasi scenario data.

TASK
Evaluasi setiap skenario dan simpulkan bukti bahwa workflow aman untuk penggunaan ulang.

RULES
Nilai PASS hanya bila jenis error, warning code, output policy, dan log cocok; sebutkan keterbatasan uji.

EXPECTED OUTPUT
Matriks PASS/FAIL dengan bukti, masalah yang tersisa, dan prioritas tindak lanjut.

VERIFICATION
Cross-check lima JSON Run Report, lima log, dan ketiadaan CSV pada critical failures.

Tiga Refleksi Peserta

Refleksi 1: Mengapa pipeline yang sama bisa untuk baseline dan Juli?

Perbedaan skema data dan jalur (file path) dikelola secara dinamis melalui parameter konfigurasi.

Refleksi 2: Mengapa missing input harus STOP tanpa membuat CSV final?

Missing input harus STOP, jika terjadi missing input untuk mencegah data corruption atau null records.

Refleksi 3: Mengapa campaign_name opsional boleh warning dan lanjut?

Atribut campaign_name bersifat opsional (nullable) pada skema contract untuk memfasilitasi transaksi non-kampanye.

Kesimpulan dan Batasan
